# Generic Types, Collections, and Strings

Use the repository's existing types and operations before implementing local
versions. This guide introduces the APIs; the linked headers and their tests
are the authority for signatures, ownership, capacity, and failure behavior.

## Find the Existing Operation First

1. Identify the type that owns the operation and read its public API.
2. Inspect the defining macros as well as existing callers. A function such as
   `ChannelSessions__find` is generated by `FixedArrayDefine` and
   `FixedArrayBodyDefine`; its definition appears as `alias_name##__find`, not
   as the concrete function name. Search for the operation suffix and the
   collection's definition macros when a concrete-name search finds nothing.
3. Prefer an existing operation over a handwritten loop or local utility.
   Iteration macros are for work that actually needs traversal; using one does
   not make a duplicate search, filter, or copy implementation appropriate.
4. If the API lacks a useful operation, consider a minimal extension to the
   owning shared type. Keep application-specific predicates and decisions in
   the caller. Explain why existing operations do not fit before adding a
   helper, and add tests for the new operation's behavior and edge cases.

Do not introduce an API solely for possible future callers. A current need and
a clear responsibility in the shared type justify considering an extension;
the ability to invent more parameters does not.

## Where the Types Live

Most implementations are under [common/types](../../common/types). Headers under
[kernel/types](../../kernel/types) and [user/lib/types](../../user/lib/types) adapt
shared types to their environment, including allocation. Follow the include
and definition patterns of neighboring code. Do not introduce kernel or
architecture dependencies into shared types or userspace to obtain a helper.

Collection macros generate functions prefixed with the chosen alias and `__`.
In the following sections, `Alias__find` means the generated function for that
alias, not a literal function named `Alias__find`. Follow existing placement of
declaration and body macros to avoid duplicate definitions.

## Optional and Result

- [Optional](../../common/types/optional.h) represents presence or absence.
  `OptionalDef(T)` defines the type; `Optional(T)`, `Some(T, value)`, and
  `None(T)` use it. Consume it with `match_optional(expression, some_branch,
  none_branch)` or `unwrap_optional(expression, fallback)` when an explicit
  fallback is appropriate.
- [Result](../../common/types/result.h) represents success or a failure with a
  code and `BString` message. Use `ResultDef(T)`, `Result(T)`,
  `Success(T, value)`, and `Error(T, message, code)`. Consume it with
  `match_result(expression, success_branch, error_branch)`. Use
  `unwrap_result(expression, fallback)` only when replacing a failure with a
  fallback is intentional.
- Reuse existing type definitions rather than declaring the same specialization
  again. Never inspect Optional or Result storage fields directly.
- Use Optional for an ordinary missing value and Result for an operation that
  can fail. Return a named struct wrapped in one of these types when several
  values belong to one result; do not use scalar out-parameters and a boolean
  status to recreate a result type.

## Fixed Arrays

[FixedArray](../../common/types/fixed_array.h) is a typed collection with a fixed
capacity and a current length. `FixedArrayDefine(type, size, alias, equals)`
declares it; `FixedArrayBodyDefine(alias)` supplies its generated operations.

| Need | Existing operation |
| --- | --- |
| Initialize or query length | `Alias__init`, `Alias__new`, `Alias__len` |
| Search using a predicate and context | `Alias__find` |
| Locate a value using the configured equality function | `Alias__find_item` |
| Select matching elements | `Alias__filter` |
| Read a value or obtain a pointer to an element | `Alias__at`, `Alias__ptr_at` |
| Add, replace, or remove elements | `Alias__push`, `Alias__push_all`, `Alias__set`, `Alias__remove` |
| Remove an element from an end | `Alias__pop`, `Alias__pop_front` |
| Produce sorted values | `Alias__sort_asc`, `Alias__sort_desc` |
| Traverse elements when no operation fits | `for_each_fa`, `for_each_fa_ptr` |

`__find` accepts a predicate taking an element pointer and a context pointer.
It returns an optional find result. Use
[`match_find_result` or `match_find_result_ptr`](../../common/types/find_result.h)
to obtain the matching element as a value or pointer. `__find_item` instead
accepts an element value and returns `Optional(ArrayIndex)`.

For example, checking whether `ChannelSessions` contains a connection ID is a
predicate search: use `ChannelSessions__find` with a predicate comparing the
connection ID, then match the result to determine presence. Do not write
another traversal in `ChannelSessions__contains`, or construct a dummy
exchange solely to search for one field with `__find_item`.

Use `Alias__init` when the collection already has storage, especially for large
fixed arrays where returning a new collection value would create a large
temporary. `Alias__new` remains appropriate for ordinary local values.

Check whether an operation returns a copy or a pointer before mutating an
element. In particular, the `_ptr` suffix on `for_each_fa_ptr` refers to the
array argument being a pointer; its iteration value is still copied. Use
`__ptr_at` or `match_find_result_ptr` when the stored element must be modified.
Do not access backing arrays or length fields directly, and do not retain
element pointers across operations that move or remove elements.

## Other Collections

[Cache](../../common/types/cache.h) defines typed, bounded caches with
`CacheDefine` and `CacheBodyDefine`. `Alias__get` returns an Optional value and
promotes the entry after a repeated access. `Alias__put` inserts or updates and
reports whether it inserted, updated, or evicted an entry. `Alias__replace`
updates only a resident entry, `Alias__invalidate` removes a key, and
`Alias__len` reports occupancy. Eviction is scan resistant: one-off entries are
probationary and the oldest probationary entry is replaced before a frequently
used entry. Keep domain fetch, persistence, coherence, and diagnostics outside
the generic type.

[AtomicFixedArray](../../common/types/atomic_fixed_array.h) is the fixed-slot
variant for shared scalar storage. Define it with
`AtomicFixedArrayDefine(type, size, alias)`. It has no length field and never
compacts slots. Its layout is exactly the underlying scalar array, with the
scalar's alignment. Element types must support lock-free atomic loads/stores.

Use `Alias__new` before publication, `Alias__capacity`, `Alias__at` for an
acquire load, and `Alias__set` for a release store. Indexed reads return an
Optional; writes return a Result and reject out-of-range indices. Zero is an
ordinary value; the caller decides whether it represents an empty slot.
`for_each_atomic_fa_ptr` visits every index, loading each slot atomically when
visited. It supports `break` and `continue` but does not produce a consistent
snapshot of the entire array. Writers still need their own serialization for
multi-step updates. Never access the backing storage directly or copy/reset an
array while it is shared. Atomic message queue arrivals use this type to retain
stable connection slots while the kernel publishes and clears handles.

- [LinkedList](../../common/types/linked_list.h) provides `LinkedListDefine` and
  `LinkedListBodyDefine`, with generated `__new`, `__len`, `__push`, `__at`,
  `__ptr_at`, `__find`, `__find_item`, `__remove`, `__remove_at`, and `__dispose`
  operations. Use `for_each_ll` or `for_each_ll_ptr` for traversal that is not
  already covered by an operation. Check node and value ownership before
  removal or disposal.
- [Map](../../common/types/map.h) provides `MapDefine(K, V, size, alias, equals)`
  and `MapBodyDefine(alias)`. Use `__get` or `__get_ptr` for lookup, `__set` for
  insertion or replacement, `__delete` for removal, and `__len`/`__key` for
  queries. Traversal macros are `for_each_map` and `for_each_map_ptr`. This
  implementation uses fixed-capacity storage and linear key lookup; do not
  assume hash-table complexity or scan entries manually for a key.
- [Hashtable](../../common/types/hashtable.h) provides fixed-capacity hashed lookup
  with bounded collision buckets. Use `__new` to construct a value or `__init`
  to initialize existing storage without creating a large temporary. Use `__get` or `__get_ptr` for lookup,
  `__set` for insertion or replacement, `__delete` for removal, and `__len`
  for the number of stored entries. Traverse entries with `for_each_hashtable` or
  `for_each_hashtable_ptr`.
- [RingBuffer](../../kernel/types/ring_buffer.h) is the kernel's character ring
  buffer. Its generated operations include `__push`, `__push_all`, `__pop`,
  `__drain`, `__reset`, `__item_count`, and `__free_space`. Use these instead
  of manipulating read/write cursors or reproducing wraparound arithmetic.

Handle the returned Optional or Result from fallible collection operations.
Capacity exhaustion and missing entries are part of the API contract.
All match macros infer their payload type from the matched expression, including
value and pointer collection results. Callers must not name generated typedefs
such as `Alias__type`, `Alias__type_ptr__optional`, or `Alias__value_type_ptr`;
those names are private to the collection macros.

Use `FixedArrayStackBodyDefine` instead of `FixedArrayBodyDefine` for fixed
arrays that are constructed only in existing storage and must not depend on an
allocator. It provides the same value constructor and collection operations but
does not emit the `__heap_new` implementation.

`HashtableDefine` declares `AliasBucketPtr` for use inside collection
implementations. Application code should use the public collection operations
and traversal macros rather than accessing buckets directly.

## Atomic Records

For coherent compound records shared with read-only observers, use
`AtomicRecordArrayDefine(Type, capacity, Alias)` from `atomic_record_array.h`
after `ResultDef(Type)`. Zero the storage before publication. `Alias__set`
publishes a record; `Alias__at` returns `Result(Type)` and can report
`ATOMIC_RECORD_BUSY` or `ATOMIC_RECORD_INVALID`. Writers to each slot must be
externally serialized. Readers never write the storage. Atomic byte storage and
per-record generations prevent torn records without making the whole array a
transaction. Device and process registries use this type.

## Strings

[BString](../../common/types/bstring.h) stores bounded text with a separate length.
Use `bstr("literal")` for literals, `empty_bstr()` for an empty value, and
`BString__new` or `BString__from_chars` for runtime input as appropriate.

| Need | Existing operation |
| --- | --- |
| Length or emptiness | `BString__length`, `BString__is_empty` |
| Equality, hashing, prefix, or character membership | `BString__equals`, `BString__hash`, `BString__starts_with`, `BString__contains_char` |
| Read characters | `BString__char_at`, `BString__char_at_or` |
| Edit characters | `BString__push_char`, `BString__insert_char`, `BString__set_char_at`, `BString__remove_at` |
| Split or extract text | `BString__split`, `BString__split_first_any`, `BString__split_first_token`, `BString__slice`, `BString__strip` |
| Combine or format text | `BString__append`, `BString__join`, `BString__sprintf`, `BString__vsprintf` |
| Parse unsigned integers | `BString__parse_uint64`, `BString__parse_uint64_base` |
| Adapt to an interface requiring character buffers | `BString__cstr`, `BString__copy_to` |

Do not access string fields or recreate these operations with raw buffer
loops. Check whether a function mutates its argument or returns a new string,
and handle capacity limits and parse failures. Use character-buffer adapters
only where the receiving interface requires them.

[DynString](../../common/types/dyn_string.h) provides dynamically allocated text
when growth is required. It has `__init`, `__reserve`, `__push_char`,
`__append_cstr`, `__append_bstring`, `__clear`, `__dispose`, `__length`,
`__capacity`, `__char_at`, `__char_at_or`, `__cstr`, `__bstring`, and `__lines`
operations. Handle allocation results and dispose owned storage. Conversion
to BString is optional because the text may not fit its bound.

## Extending an API

Add a function to the type that owns the behavior when it fills a current gap
and can serve callers without depending on their domain. Prefer a small
predicate-based or value-based operation over application-specific fields or
flags in a generic type. Keep domain-specific wrappers only when they add a
meaningful policy or name, and implement them using the built-in operation.

Follow the existing `Type__method(self, ...)` naming, pointer typedefs, typed
return values, and allocation conventions. Test the extension alongside the
existing [shared type tests](../../test/shared/types),
[kernel type tests](../../test/kernel/types), or
[userspace type tests](../../test/user/types), as appropriate. Cover relevant
empty, missing, full, boundary, and mutation cases. Update this guide if the
extension changes how callers should choose or use an operation.
